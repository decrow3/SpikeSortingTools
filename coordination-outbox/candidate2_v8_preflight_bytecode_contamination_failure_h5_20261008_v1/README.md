# Candidate2 v8 pre-read bytecode-contamination failure

The single authorized v8 systemd attempt started once under invocation `9c3546f5fd314f019f412d2b74666c1f`. The complete production preflight passed and wrote `PREFLIGHT.json` with `recording_opened=false` and `recording_bytes_read=0`. The immediately following main bootstrap then failed closed before opening the recording because the preflight import had created `testing/__pycache__/candidate2_cache_managed_preflight.cpython-312.pyc` inside the exact source closure.

The implementation cause is bounded: the preflight bootstrap launches its inline import with Python `-I`; isolated mode ignores the service's `PYTHONDONTWRITEBYTECODE=1` environment, and the inline code did not set `sys.dont_write_bytecode=True`. Thus the preflight's initial source check passed, its import generated bytecode, and the main bootstrap's repeated source check correctly rejected the new file.

The target exited 1 and the external monitor recorded terminal failure. No recording was opened, no voltage was read, no sort/GPU science work began, and no output root was created. The launch directory and generated bytecode remain preserved in place. The no-retry contract was honored; a corrected attempt requires a fresh namespace, contract, review and authorization.
